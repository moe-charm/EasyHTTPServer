# EasyHTTPServer 2 製品方針

更新日: 2026-08-19

## 1. 目的

EasyHTTPServer 2は、ファイルを渡したい人や手作りのホームページを見せたい人が、サーバー運用の知識を要求されずに安全な公開を開始できるWindowsデスクトップアプリケーションです。

旧版の価値は、HTTPを自作していたことではなく、次の短い操作でファイル共有と静的ホームページ表示を成立させたことにあります。

1. 公開するファイル共有またはWebサイトフォルダーを選ぶ。
2. 待ち受けを開始する。
3. 表示されたURLを相手へ渡す。

新版でも、この操作モデルを中心に据えます。

## 2. 想定利用者

- 同じPC上で一時的にファイルを確認したい人
- 信頼できるLAN内で、大きなファイルや多数のファイルを渡したい人
- 専用クラウドへアップロードせず、手元のファイルを直接共有したい人
- HTML/CSS/JavaScriptの授業や学習で、教材を同じPCや教室のLANへ表示したい人
- 手作りの静的ホームページを、難しいサーバー設定なしで確認したい人
- 2005年版EasyHTTPServerの使用感や歴史を楽しみたい人

インターネットへ直接ポートを公開する用途は、初期版の対象外です。

## 3. 製品原則

### 3.1 明示的に選択したものだけを公開する

アプリケーションの設定、ログ、実行ファイルのあるフォルダーは自動公開しません。利用者が追加した共有ルート、またはWebサイトモードで明示選択した単一サイトルートだけを対象にします。

### 3.2 初期状態ではローカル限定にする

初回起動時はループバックアドレスだけで待ち受けます。LAN公開は、公開範囲とリスクを表示したうえで利用者が明示的に有効化します。

### 3.3 初期版は読み取り専用にする

対応メソッドはGETとHEADを基本とします。アップロード、削除、更新、CGIは、読み取り専用サーバーとは別の脅威モデルを必要とするため含めません。

### 3.4 HTTPを自作しない

HTTPの解析、接続管理、タイムアウト、Range応答などはKestrelとASP.NET Coreへ委譲します。アプリケーション固有の実装は、共有ルート、認可、目次、状態表示に集中させます。

### 3.5 UIとサーバーを分離する

WPF画面はHTTP要求を直接処理しません。サーバーの開始・停止と状態取得は抽象化されたインターフェースを通します。将来、ヘッドレス版やWindowsサービス版を追加しても、サーバーコアを再利用できる構造にします。

### 3.6 旧版を歴史資料として保存する

配布版、ソース、README、アイコン、バージョン情報を保存します。新版へ必要な情報を移したあとも、旧ファイルを新しい実装で上書きしません。

### 3.7 公開目的を混在させない

ファイルを渡す「ファイル共有」と、HTML/JavaScriptを実行する「Webサイト」は、共有セッション全体で排他的なモードにします。Webサイトは単一の専用ルートと開始ごとのfresh originを使い、複数のファイル共有や別のサイト開始セッションと同じoriginへ載せません。

## 4. 初期リリースの機能範囲

### 必須

- 複数共有フォルダーの追加・削除
- サーバーの開始・停止
- ループバックとLANの待ち受け設定
- 共有ごとの一意なURLスラッグ
- 日本語等の表示名でも再追加時に変わらない、短く安全なURLスラッグ
- 自動ディレクトリ目次
- ファイルダウンロード
- GET、HEAD、単一Rangeへの対応
- MIMEタイプ判定と未知形式の安全なダウンロード
- 接続・転送状態の一覧
- URLのコピー
- バージョン付きJSON設定
- 構造化ログと秘密情報の除外
- ModernテーマとClassic 2005テーマ
- ファイル共有／Webサイトの明示的なモード選択
- 単一サイトルートの`index.html`または`index.htm`表示
- HTML、CSS、JavaScript、画像、音声、動画、フォント等の静的サイト配信
- ネストしたディレクトリ、末尾slash、相対URLへの対応
- ファイル共有、別サイト、別開始セッションを分離するfresh origin
- WebサイトのHTML/JavaScript実行を開始前に伝える確認

### 初期版では行わない

- ファイルアップロード
- ファイル削除・移動・名前変更
- CGI、PHP、Perl等のプロセス起動
- WebDAV
- インターネット向けの自動ポート開放
- UPnPによるルーター設定
- グローバルIPから外部公開URLを自動生成すること
- プラグイン実行
- 複数サイトの同時公開
- SPAフォールバック
- Service Worker / PWA
- 外部CDNや外部APIを許可するCSP編集

## 5. 成功条件

製品アイコンは、猫型サーバー本体、共有を表す左右のフォルダーノード、稼働状態を表すランプを単一のシルエットへまとめます。文字を入れず透明背景とし、Windowsの16px表示から高解像度表示まで同じブランドを維持します。

- 利用者が3操作以内でローカル共有を開始できる。
- キーボードとスクリーンリーダーでも主要操作と現在状態を識別できる。
- 選択した共有ルートまたは単一サイトルート外のファイルを、URL表現やjunction等を変えても取得できない。
- 10GB級ファイルをメモリへ全読み込みせず配信できる。
- 中断したダウンロードをRange要求で再開できる。
- Authorization、Cookie、パスワードがログへ残らない。
- サーバー停止時に新規接続を止め、処理中転送を定められた時間内で終了できる。
- UIを閉じたあとに待ち受けソケットやワーカースレッドが残らない。
- Webサイトモードの`/`で、実在するHTMLがダウンロードではなく通常表示される。
- HTMLから参照するCSS、JavaScript、画像、音声、動画、フォントが実ブラウザーで動作する。
- Webサイトを公開しても、非選択のファイル共有や別ルートへ到達できない。
- ファイル共有モードでは、HTML、SVG、JavaScript、XMLの添付ダウンロード方針が変わらない。
