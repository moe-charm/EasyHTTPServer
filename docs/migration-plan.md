# EasyHTTPServer 2 移行計画

更新日: 2026-08-19

## 1. 移行の考え方

旧版コードを新しい.NETへ直接アップグレードするのではなく、旧版を仕様資料として参照しながら、新しいソリューションを並行して作ります。

理由は次のとおりです。

- HTTP解析とファイル配信がUIへ密結合している。
- 1接続1スレッドである。
- パス、Range、CGI、認証に安全でない挙動がある。
- SOAP設定モデルが画面のPropertyGridと一体化している。
- テストが存在しない。
- 独自DLLの実質的な用途は、CGI拡張子の文字列分割に限られる。

## 2. 保存対象

次は歴史資料として保存します。

- 2005-11-29の配布版1.1
- 2005年の旧`readme.txt`（作者のローカル完全版で保存、公開版には非収録）
- 旧DLL群
- `legacy/source-1.2/`の1.2系ソース
- Visual Studio 2005へのUpgradeLog
- アイコン
- 旧画面とAbout画面の文言

旧ファイルは、アーカイブ方針とチェックサムを確定するまで移動しません。

## 3. 公開対象から除外するもの

- `Save/`
- `log/`
- `legacy/source-1.2/bin/`
- `legacy/source-1.2/obj/`
- `.suo`
- `.user`
- `.pwd`
- 実在する認証情報や個人用フォルダーパスを含むファイル

Git初期化より前に`.gitignore`を作り、追跡対象を確認します。

## 4. 段階

### Phase 0: 来歴と境界の確定

- ファイル一覧、バージョン、日時、CLRバージョンを記録する。
- 配布版とソース版実行ファイルのSHA-256を記録する。
- CP932の旧ソースをバイト単位で保存する。
- 新版の正式名称とライセンスを決める。
- 旧設定とログを公開対象から除外する。

完了条件:

- 旧版を変更せず復元できる。
- 公開してはいけないファイルが一覧化されている。

### Phase 1: 新ソリューション骨格

- .NET 10の新しいソリューションを作る。
- Core、Server、Desktop.Wpf、テストプロジェクトを作る。
- 依存方向をビルドで検証する。
- 警告をエラーとして扱う。
- Nullableを有効にする。
- Windows CIを追加する。

完了条件:

- クリーンチェックアウトからrestore、build、testが成功する。
- WPFを参照しないServerテストが実行できる。

### Phase 2: ローカル読み取り専用サーバー

- ループバック限定でKestrelを起動する。
- 共有追加と完全一致ルーティングを実装する。
- 安全なパスリゾルバーを実装する。
- GET、HEAD、Rangeを実装する。
- 自動目次を実装する。
- 停止とGraceful Shutdownを実装する。

完了条件:

- パス攻撃テストが通る。
- 大容量ファイルを定数メモリで配信できる。
- curlとブラウザーでGET、HEAD、Rangeを確認できる。

### Phase 3: WPF GUI

- 共有フォルダー一覧を実装する。
- 開始・停止を実装する。
- 接続と転送一覧を実装する。
- URLコピーを実装する。
- Modernテーマを実装する。
- Classic 2005テーマとHistory画面を実装する。
- 設定保存を実装する。

完了条件:

- 「フォルダー追加、開始、URLコピー」で共有できる。
- 転送中もUIが応答し続ける。
- 終了後にサーバープロセスや待ち受けが残らない。

### Phase 4: LANとセキュリティ

- LAN公開の確認画面を実装する。
- HTTPS証明書方針を確定・実装する。
- 認証を実装する。
- ログ秘匿とローテーションを実装する。
- Kestrel制限とレート制限を調整する。
- Windowsファイアウォールの案内を実装する。

完了条件:

- パスワードが平文通信・平文設定・ログへ現れない。
- LAN公開の範囲をUI上で確認できる。
- セキュリティ統合テストが通る。

### Phase 5: 静的Webサイトの中核価値を復元

このMigration Phase 5は、[現在のタスク](../current_task.md)のP7に対応します。

- ファイル共有とWebサイトを排他的な`Publication`へ分離する。
- machine-wide単一起動と役割付きorigin port履歴を実装し、49152〜65535のbrowser-safe候補から開始ごとのfresh originを割り当てる。FileShare reservedをWebsiteへ、Website retiredを全modeへ再利用しない。
- `index.html`、`index.htm`、末尾slash、相対URLを実装する。
- HTML、CSS、JavaScript、画像、音声、動画、フォント等を正しいMIMEで通常配信する。
- ファイル共有側の能動形式download-onlyを回帰テストで固定する。
- Webサイト用CSP、Service Worker禁止、mode別Cookie、認証前subresource拒否を実装する。
- filesystem access前にUNC、device namespace、mapped network drive、network filesystemを拒否する。local volume rootから全ancestorをhandle-relative no-followで開いてrename不可に保持し、要求もroot基準で走査して同じ検証済みfile handleから配信する。
- settingsには両モードの入力を保持し、active `Publication`だけを排他にする。モード切替で共有一覧とsite rootを失わない。
- WPFへ3操作以内のモード選択・単一フォルダー・開始導線を追加する。

完了条件:

- 旧版で中核だった実`index.html`が、実ブラウザーで普通のホームページとして表示される。
- サイトのCSS、JavaScript、画像とネストした相対URLが動作する。
- ファイル共有、別サイト、別開始セッションが同じoriginへ混在せず、origin履歴を再起動・競合・crashで失わない。
- CGI、アップロード、ディレクトリ一覧をWebサイトへ持ち込まない。
- LAN/VPNではHTTPSとペアリング完了前に、アプリ生成pair画面を除く利用者サイト内容を返さない。

詳細は[Webサイトモード設計](website-mode.md)を正とします。

### Phase 6: 配布

- self-containedフォルダーを作成してZIP化する。
- win-x64を必須成果物とする。
- 必要ならwin-arm64を追加する。
- バージョン情報とアイコンを設定する。
- 署名方針を決める。
- 配布物だけを展開した環境で動作確認する。
- README、スクリーンショット、変更履歴を整える。

完了条件:

- .NET未導入の検証環境で起動できる。
- 配布物に設定、ログ、PDB、旧認証情報が含まれない。
- 配布物からファイル共有とWebサイトのフォルダー選択、開始、停止まで確認できる。
- HTML/CSS/JavaScript/画像を含むサンプル教材サイトを、ZIP展開版から実ブラウザーで表示できる。

## 5. 旧設定から移行する項目

| 旧項目 | 移行 |
|---|---|
| 公開フォルダー | 利用者の再確認後に移行 |
| ポート | 有効範囲を検証し、ファイル共有portだけへ移行。Webサイトportは開始ごとに新規割り当て |
| トップ仮想目次名`RootFileName`（既定`index.html`） | 移行しない。新版の物理`index.html` / `index.htm`探索は独立したWebサイト仕様 |
| 最大接続数 | 新しい上限へ丸めて移行 |
| MIME設定 | 自動移行しない。新版の明示MIME表を使い、将来も安全な許可リストだけを検討 |
| ウィンドウ位置・サイズ | 原則移行しない |
| 生成目次の先頭・末尾HTML | 移行しない。安全なテーマへ置換。利用者作成の実HTMLとは別機能 |
| Basic認証ID/PASS | 移行しない |
| CGI設定 | 移行しない |
| 外部IP取得URL | 移行しない |

## 6. 互換性の優先順位

1. 「フォルダーを選ぶ、開始、URLを渡す」という操作手順
2. 実`index.html`と関連素材を普通のホームページとして表示できること
3. 共有URLとディレクトリ構造の分かりやすさ
4. 大容量ダウンロードと再開
5. 旧版の見た目と歴史
6. 詳細設定

危険な挙動とのバグ互換は維持しません。
